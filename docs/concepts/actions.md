# Actions

An action is one thing the app can do. It is a class that extends `AgentAction<Input, Output>`. Screens, the assistant and the command line all run it through one `ActionRegistry`.

## Why

The registry is the only way to change data. So the assistant can do whatever the UI can, every change leaves a receipt, and a test of the action tests every caller.

## The parts of an action

- **`name` and `description`.** The model reads them to choose a tool. The name is `snake_case`.
- **`input`, a schema.** It describes the input as JSON for the model, checks it, and builds the typed input. Every field has a description.
- **`run`.** It does the work. On failure it throws `ActionFailure(code, message)`. It never returns an error value and never calls a model. When a run fails after it already wrote something, the registry puts the receipts recorded so far on the `ActionFailure`, so a partial write still shows.
- **`resources`.** The data it writes. After each call to an action that writes (not `readOnly`), the registry sends a change event for each of these resources, so screens refresh.
- **`encode`.** It turns the output into the JSON the model gets back.

This is `create_item`, from [`lib/domain/actions/items_actions.dart`](../../lib/domain/actions/items_actions.dart):

```dart
  @override
  List<String> get resources => const ['items'];

  @override
  List<String> get searchHints => const ['add', 'new'];

  @override
  Future<Item> run(CreateItemInput input, ActionContext context) async {
    final description = _description(input.description ?? '');
    final created = await items.createItem(
      title: _title(input.title),
      description: description.isEmpty ? null : description,
    );
    final stored = await items.getItem(created.id);
    context.receipt(
      resource: 'items',
      ids: [created.id],
      summary: 'Created item "${created.title}"',
      key: 'created_item',
      args: {'title': created.title},
      verified: stored != null,
    );
    return stored ?? created;
  }
```

`_title` throws `ActionFailure('invalid_input', ...)` when the title is blank or too long. The check is in `run`, not only in the schema, because screens pass typed input that skips the schema.

## The registry

Every action is listed in `AppActions` and put into one registry, from [`lib/domain/actions/app_actions.dart`](../../lib/domain/actions/app_actions.dart):

```dart
/// The registry the UI, the assistant and the CLI share: the app's actions
/// plus the built-in ones.
ActionRegistry buildActionRegistry(
  AppActions actions, {
  required AppContext appContext,
  required MemoryStore memories,
}) => ActionRegistry([
  ...actions.all,
  ...builtInActions(appContext: appContext, memories: memories),
]);
```

A screen calls `registry.run(actions.createItem, input)` with typed input. The assistant and the command line call `registry.call(name, json, caller: ...)`; `call` refuses `Caller.ui`, so JSON input from a screen can never skip approval. Try it:

```bash
dart run tool/action.dart --list
dart run tool/action.dart create_item '{"title":"Milk"}'
dart run tool/action.dart create_item '{"title":""}'
```

The last call fails with `invalid_input` and exit code 1.
